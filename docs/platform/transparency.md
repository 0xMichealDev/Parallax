# Evidence & transparency

Understand what PARALLAX verifies—and what it does not.

[Live guide](https://parallaxlaunch.live/docs/transparency) · [Guide index](README.md)

Useful research shows its evidence, time and limits. A polished interface is not a substitute for checking the underlying records.

## Evidence has a scope

Read source links and timestamps. Market data can be delayed, incomplete or specific to a single pair. An unavailable value is unknown, not zero. AI explanations can make mistakes and should be checked against the selected evidence.

## Verification is specific

A wallet signature proves control at the time of the proof. SolHandle ownership establishes a current name-to-wallet relationship. Neither independently proves a person’s identity, a token’s legitimacy or a project’s future performance.

## Interpreting external scanners

Inspect each named risk and its evidence. Separate protocol reserves from ordinary holder balances, and distinguish historical classifications from current permissions. Publishing documentation or code is not an audit and does not automatically change a third-party risk score.

## Privacy and sharing

Saved research and Assistant conversations belong to the signed-in account. Public report sharing is an explicit action. Pro monitoring lists are saved locally for the verified wallet and do not automatically sync across devices. Avoid putting private information into public project profiles or shared reports.

## Report a problem

For a general product issue, describe the page, time, expected result and what happened in the [PARALLAX community](https://t.me/Parallaxcommunity). For a possible vulnerability, ask a project administrator for a private reporting channel before sharing details. Never post passwords, seed phrases, signatures or API credentials in a public report.
